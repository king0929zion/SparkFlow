# SparkFlow Web 控制中心

`docs/` 目录现在提供与 SparkFlow 主程序直接对应的 Web 控制中心。它负责配置生成、账号任务编辑、运行前检查、定时计划生成和 GitHub Actions 状态展示；真正的任务执行仍由 GitHub Actions 中的 Python + Playwright 完成。

## 控制中心能做什么

- 生成与 `utils/config.py` 一致的 Environment Variables。
- 管理多账号 `TASKS` 配置。
- 为每个账号生成 `COOKIES_<UNIQUE_ID>` Environment Secret 键名。
- 对用户提供的 Cookie JSON 做本地结构检查。
- 生成 `.github/workflows/schedule.yml` 可使用的 `cron` + `timezone` 片段。
- 读取公开仓库真实的 GitHub Actions Workflow 和 Run 状态。
- 在执行前检查账号、Cookie、目标好友和定时计划。

## 与 Python 配置的对应关系

| 控制中心字段 | Python 配置 | 用途 |
| --- | --- | --- |
| `PROXY_ADDRESS` | `proxyAddress` | 代理地址，目前业务逻辑暂未实现 |
| `MESSAGE_TEMPLATE` | `messageTemplate` | 消息模板 |
| `HITOKOTO_TYPES` | `hitokotoTypes` | `[API]` 每日一言分类 |
| `MATCH_MODE` | `matchMode` | `nickname` / `short_id` |
| `BROWSER_TIMEOUT` | `browserTimeout` | 浏览器最大等待时间 |
| `FRIEND_LIST_WAIT_TIME` | `friendListTimeout` | 好友列表等待时间 |
| `TASK_RETRY_TIMES` | `taskRetryTimes` | 任务重试次数 |
| `LOG_LEVEL` | `logLevel` | 日志级别 |
| `TASKS` | `get_userData()` | 多账号任务列表 |
| `COOKIES_<UNIQUE_ID>` | `get_userData()` | 每个账号独立的 Cookie Secret |

默认消息模板：

```text
[盖瑞]今日火花[加一]\n—— [右边] 每日一言 [左边] ——\n[API]
```

## 账号任务

每个账号在控制中心中包含：

- `USERNAME`：日志和界面中的账号标识。
- `UNIQUE_ID`：账号唯一标识，同时决定对应的 Secret 键名。
- `COOKIES`：用户自行提供的 Cookie JSON，仅在当前页面内存中用于格式检查。
- `TARGETS`：当前账号需要匹配的目标好友列表。

生成的 `TASKS` 结构与主程序直接兼容，例如：

```json
[
  {
    "username": "主账号",
    "unique_id": "123456789",
    "targets": ["好友A", "好友B"]
  }
]
```

对应的 Environment Secret 键名为：

```text
COOKIES_123456789
```

## Cookie 安全模型

控制中心不会把 Cookie 写入本地草稿，也不会批量导出 Cookie 值。

页面只做以下本地检查：

1. 内容能否解析为 JSON。
2. 顶层是否为非空数组。
3. Cookie 项是否具备程序常用的字段结构。
4. 是否能识别出与抖音域名相关的数据。

这些检查用于尽早发现格式问题。登录态是否仍然有效，需要通过一次真实的 GitHub Actions 运行确认。

## 好友匹配

`MATCH_MODE=nickname` 时，`TARGETS` 填写好友昵称。

`MATCH_MODE=short_id` 时，`TARGETS` 填写好友抖音号，用于降低好友修改昵称后匹配失效的概率。

## 运行前检查

控制中心“运行态”会显示四项真实本地检查：

- 账号与 `UNIQUE_ID`
- Cookie JSON
- 目标好友
- 定时计划

四项全部满足后显示 `4 / 4`。这表示配置结构已经准备好，不代表远端任务已经实际执行成功。

## GitHub Actions 状态

控制中心从公开 GitHub API 读取真实 Workflow / Run 数据。

有运行记录时，会展示运行结论、触发事件、分支、运行编号和时间，并链接到对应 GitHub Run。

如果 GitHub 返回 0 个 Workflow 或 0 条 Run，页面会明确显示“未索引 / 暂无记录”，不会使用模拟数据。

## 部署

配置完成后进入“部署输出”：

1. 把 Environment Variables 写入 GitHub Environment `user-data`。
2. 按页面生成的 `COOKIES_*` 键名创建 Environment Secrets。
3. 如果修改了执行时间，把“定时计划”生成的片段提交到 `.github/workflows/schedule.yml`。
4. 在 GitHub Actions 中手动运行一次，验证真实执行结果。

详细步骤见：[GitHub Actions 部署说明](Action部署说明.md)。
