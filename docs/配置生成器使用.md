# SparkFlow Web 控制中心

`docs/` 是 SparkFlow 的静态控制中心。它与 `main` 中的统一配置模型对应，只负责配置生成、Cookie 本地结构检查、定时计划生成和公开 Actions 状态展示；实际自动化仍由 GitHub Actions + Python + Playwright 执行。

## 配置对应关系

| 控制中心字段 | Python 配置 | 用途 |
| --- | --- | --- |
| `PROXY_ADDRESS` | `proxyAddress` | 代理地址预留 |
| `MESSAGE_TEMPLATE` | `messageTemplate` | 消息模板 |
| `HITOKOTO_TYPES` | `hitokotoTypes` | `[API]` 每日一言分类 |
| `MATCH_MODE` | `matchMode` | `nickname` / `short_id` |
| `BROWSER_TIMEOUT` | `browserTimeout` | 浏览器超时 |
| `FRIEND_LIST_WAIT_TIME` | `friendListTimeout` | 列表等待时间 |
| `TASK_RETRY_TIMES` | `taskRetryTimes` | 操作重试次数 |
| `LOG_LEVEL` | `logLevel` | 日志级别 |
| `TASKS` | account tasks | 多账号任务 |
| `COOKIES_<UNIQUE_ID>` | account cookies | 每账号独立 Secret |

## Cookie

Cookie 必须从：

```text
https://www.douyin.com/chat
```

导出。控制中心不会持久化 Cookie，只在当前页面内存中检查 JSON 结构和 `douyin.com` 域名信息。

Python 配置层会在运行时再做一次严格标准化，支持 Cookie-Editor 常见的 `domain + path` 结构，也兼容 Playwright 的 `url` 结构。

## 好友匹配

`MATCH_MODE=nickname`：`TARGETS` 填昵称或备注名。

`MATCH_MODE=short_id`：`TARGETS` 填抖音号，程序会利用 Web IM 返回的用户信息映射到会话列表。

## 部署输出

控制中心生成结果后：

1. Environment Variables 写入 GitHub Environment `user-data`。
2. `COOKIES_*` 写入同一个 Environment 的 Secrets。
3. 定时计划只提交到 `main/.github/workflows/schedule.yml`。
4. 首次运行先选择 `Actions -> SparkFlow -> mode: smoke`。
5. smoke 通过后再选择 `mode: send`。

`send` 自己仍会再执行一次 smoke 预检，因此控制中心、本地 CLI 和 GitHub Actions 的能力不会因为不同入口而分叉。

## GitHub Actions 状态

控制中心读取公开 GitHub API 的真实 Workflow / Run 数据，不使用模拟记录。

业务工作流固定为 `schedule.yml`。仓库同时存在 `ci.yml` 和 `branch-policy.yml`，分别负责代码回归测试和 main-only 分支策略，它们不承载抖音发送能力。

## 单分支原则

仓库只保留：

```text
main
```

不要通过 `api`、`dev`、`feature/*` 分支维护不同能力。如果需要调整功能，直接让 `main` 中的统一入口支持明确的运行模式，并由 CI 与 smoke 保护回归。

详细部署步骤见 [GitHub Actions 部署说明](Action部署说明.md)，架构边界见 [架构说明](架构说明.md)。
